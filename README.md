# Ужгород · Погода

Погодна панель для Ужгорода: поточні умови, прогноз на найближчі години й тиждень, штормові попередження, офіційні спостереження та якість повітря з локальних станцій.

**[Відкрити сайт →](https://ungvar-v.github.io/weather/)**

## Можливості

- **Погода зараз:** температура, відчутна температура, вітер і пориви, вологість, тиск на рівні моря та опади за останній інтервал моделі. Анімований фон відповідає стану погоди та часу доби.
- **Найближчі 24 години:** графік температури, погодні іконки та ймовірність опадів. Натискання або наведення на точку показує деталі години.
- **Прогноз на 7 днів:** погода, мінімальна й максимальна температура за добу, максимальна швидкість вітру, ймовірність і сума опадів.
- **Штормові попередження:** повний текст чинних попереджень Закарпатського ЦГМ, рівень небезпечності, час випуску та посилання на джерело — у верхній частині сторінки.
- **Локальні станції:** карта трьох станцій, температура, вологість, дрібний пил PM2.5 та індекс якості повітря AQI з текстовим поясненням і кольором рівня.
- **Спостереження ЦГМ:** останній фактичний вимір станції 33631, графік температури й тиску та компактна таблиця історії з прокручуванням.
- **Офіційний прогноз:** Ужгород, Закарпатська область і наступні дні. Температури винесені в заголовки карток, решта змісту прогнозу збережена; якщо формат тексту зміниться й не розпізнається, він показується без такого поділу.

Інтерфейс українською, адаптується до вузьких екранів. Погодні іконки — вбудовані SVG, без залежності від системних емодзі. Анімація враховує налаштування зменшення руху на пристрої.

## Як працює оновлення

1. Зовнішній планувальник **cron-job.org кожні 15 хвилин** запитує запуск GitHub Actions через `workflow_dispatch`.
2. Workflow **Update weather data** запускає `update_data.py`: він опитує джерела, формує `data.json` і зберігає зміни в `main`.
3. GitHub Pages віддає інтерфейс. На опублікованому сайті свіжий `data.json` завантажується з поточної гілки репозиторію, з резервним читанням файлу поруч зі сторінкою.
4. Відкрита сторінка перевіряє дані **кожні 5 хвилин** і після повернення до вкладки. Якщо поточна модельна оцінка відсутня або старша за 30 хвилин, браузер також пробує отримати її безпосередньо з Open-Meteo.

У самому workflow додатково залишений розклад `7,37 * * * *` — о 7-й та 37-й хвилині кожної години. **Інтервал 15 хвилин забезпечує окреме завдання cron-job.org**, а не цей вираз. Після копіювання репозиторію зовнішній розклад треба налаштувати окремо.

Оновлення файлу не означає новий вимір кожного датчика. Спостереження ЦГМ надходять у строки приблизно **раз на 3 години**, інші джерела мають власну періодичність. Час виміру, час модельного розрахунку та час оновлення файлу — різні значення; вони показуються окремо. Час моделі та спостережень ЦГМ наведено за Києвом, часові позначки локальних станцій — як їх передає джерело.

Ручне оновлення: **[Actions → Update weather data](https://github.com/Ungvar-V/weather/actions/workflows/update-weather.yml) → Run workflow → main**.

### Зовнішній запуск раз на 15 хвилин

Для повторного налаштування завдання cron-job.org:

- Розклад: `*/15 * * * *`.
- Метод: `POST`.
- URL: `https://api.github.com/repos/Ungvar-V/weather/actions/workflows/update-weather.yml/dispatches`.
- Заголовки: `Accept: application/vnd.github+json`, `Content-Type: application/json`, `Authorization: Bearer <GITHUB_TOKEN>`.
- Тіло запиту: `{"ref":"main"}`.

Потрібен токен із доступом до цього репозиторію та дозволом **Actions: write**. Токен зберігається в налаштуваннях планувальника, не в публічних файлах. Подробиці API — у [документації GitHub](https://docs.github.com/en/rest/actions/workflows#create-a-workflow-dispatch-event).

## Як читати показники

- **«Погода зараз» — модельна оцінка Open-Meteo.** Це не прямий вимір міського датчика. Фактичні виміри ЦГМ і локальних станцій показані в окремих блоках із власним часом.
- **Мін. / макс.** у тижневому прогнозі — найнижча й найвища температура за добу, а не окремий прогноз на ніч і день.
- **Опади:** відсоток — імовірність, міліметри — прогнозована кількість за добу. Вони описують різні речі. У поточній погоді вказаний окремий, коротший інтервал.
- **AQI** — індекс якості повітря за дрібним пилом PM2.5, отриманий від SaveEcoBot. Що більше число, то вище забруднення. Поруч із числом показані зрозуміла назва та колір рівня.
- **«Немає виміру»** означає відсутні дані, а не нульове значення.

| AQI | Позначення якості повітря |
| --- | --- |
| 0–50 | Добра |
| 51–100 | Помірна |
| 101–150 | Шкідлива для чутливих груп |
| 151–200 | Шкідлива |
| 201–300 | Дуже шкідлива |
| 301 і вище | Небезпечна |

## Якщо джерело тимчасово недоступне

Джерела опитуються незалежно, тому відмова одного з них не повинна прибирати решту блоків. Для офіційних спостережень і прогнозу зберігаються попередні доступні дані з позначенням проблеми оновлення. Застарілі показники локальних станцій також позначаються.

Для попереджень обробляється кожен запис окремо: некоректний запис без розпізнаного строку дії не показується як чинне попередження і не приховує коректні. Якщо перевірка джерела не вдалася, останнє відоме попередження може залишатися до завершення його строку дії з відповідною позначкою. Коли джерело задає лише дати в тексті, завершення дії визначається кінцем останньої зазначеної дати; точне формулювання періоду залишається в повному тексті.

## Запуск локально

Потрібні Python **3.12 або новіший**, доступ до інтернету та браузер. Окремий сервер застосунку й збірка через npm не потрібні.

```sh
git clone https://github.com/Ungvar-V/weather.git
cd weather
python -m pip install requests tzdata
python update_data.py
python -m http.server 8000
```

Відкрити [http://localhost:8000](http://localhost:8000). Пакет `tzdata` забезпечує часовий пояс `Europe/Kyiv` у середовищах, де немає системної бази часових поясів, зокрема у Windows.

## Основні файли

| Файл | Призначення |
| --- | --- |
| `index.html` | Готовий інтерфейс, стилі, вбудовані погодні SVG-іконки та географія карти |
| `update_data.py` | Отримання й перевірка даних, розбір прогнозу та попереджень, формування JSON |
| `data.json` | Останній зібраний набір даних із часом і статусом джерел; генерується скриптом |
| `.github/workflows/update-weather.yml` | Запуск збирача та запис оновленого JSON у репозиторій |
| `README.md` | Опис можливостей, джерел, оновлення та запуску |

Графік історії використовує **Chart.js**, карта — **D3**, шрифти — **Google Fonts**. Ці ресурси завантажуються через інтернет; погодні іконки та географічні дані карти вбудовані в сторінку.

## Публікація на GitHub Pages

У цьому репозиторії сайт публікується з **main / root**: **Settings → Pages → Deploy from a branch**. Для оновлення інтерфейсу достатньо зберегти зміни в `index.html`; для логіки збору — в `update_data.py`. Дані можна оновити через Run workflow.

У власній копії потрібно також перевірити дозволи GitHub Actions на запис `data.json`, налаштувати зовнішній запуск і змінити адресу репозиторію та умову домену у функції `loadWeatherPayload()` в `index.html` під власний GitHub Pages.
